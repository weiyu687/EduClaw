# 多文件长流程

## 先选合适的入口

普通解释或一次搜索用对话即可。需要读取多个来源、关联计算、写入与核对文件时使用任务模式。需要持续运行命令、观察报错并修复项目时使用持续终端 Agent。

开始前明确输入目录、目标、输出位置与不允许的操作。技能可设置偏好，但无需逐个选择工具；权限仍由当前对话模式决定。

## 示例一：项目预算对账

准备交易 CSV、预算 JSON、调整 JSONL 和规则 Markdown。将下文中的文件名替换为本机真实绝对路径，再输入任务模式：

```text
请读取我指定的交易 CSV、预算 JSON、调整 JSONL 和规则 Markdown，完成项目对账。
先分别读取四个来源，再检查 CSV 的空值和重复记录。
依据真实结果，按项目汇总交易与调整，计算净支出、预算差额和超支清单。
最后汇总计算结果、数据质量结论与规则说明，标注来源步骤。
不要修改输入文件；如果缺少必要字段，请停止并说明。
```

| 步骤 | 目的 |
| --- | --- |
| 1–4 | 分别读取四份来源 |
| 5 | 检查 CSV 空值、重复与数值列 |
| 6 | 用 Python 关联交易、预算与调整 |
| 7 | 生成数据质量核查与超支清单 |
| 8 | 汇总规则、结果与来源证据 |

平衡模式中，工作目录外读取需授权，Python 步骤需审阅；GUI 和 CLI 都可处理。自主执行只在你明确授权后自动推进。每个任务最多 12 步，模型计划可能与示例拆分不同。

## 示例二：学习进度分析

准备成绩 CSV（id、quiz、exam）、权重 JSON、出勤 JSONL 和课程说明文本，可选择 `learning-progress` 与 `data-quality` 技能偏好。

目标是按 ID 关联记录，依照实际权重计算成绩，统计出勤，标注需要进一步支持的学习者，并附上质量问题和来源。结果用于学习反馈，不自动作出处分或录取决定。

## 示例三：项目测试与修复

在持续终端面板选择项目目录，确认权限后输入：

```text
先检查当前目录的项目结构和测试入口，说明将运行哪些检查。
运行已有测试，依据真实错误定位问题并做最小修复，再次运行测试。
不要修改与报错无关的文件，不要删除数据，不要推送或发布。
最后列出修改文件、实际测试结果与尚未解决的问题。
```

Agent 会观察输出再决定下一步，不只是执行一次 Python。根据审批模式，它可能在输入前等待确认。长程序可使用停止 Agent / Ctrl+C；关闭终端会结束其子进程，但不会回滚已有修改。

## 结果、暂停与恢复

在“结果证据”核对实际输出、状态和摘要完整性。失败或不确定的步骤不会自动重放。暂停阻止后续步骤；取消请求终止当前执行。服务重启后先核查状态，再决定恢复，不要仅根据页面关闭与否判断任务是否停止。

CLI 用 `/sessions`、`/use ID` 和 `/任务 编号` 选择，`/状态`、`/结果` 查看；恢复和重规划通过相应预览与确认流程操作。GUI 支持文件、代码和工具逐步审批，重规划和更细的恢复诊断仍以 CLI 为主。

## 给开发者的中间结果约定

需要被后续引用的 Python 输出应是单个合法 JSON，例如 `print(json.dumps(result, ensure_ascii=False))`，不要混入 Markdown 或日志。使用 `{{step:N:json:/field}}` 引用前序真实结果；单个引用值最多 12000 字符，解析后代码最多 32 KiB。大数据先聚合，避免把全部原始输入塞入代码。

## 实机验收脚本

`python scripts/windows_long_workflows_e2e.py` 使用隔离合成数据、真实模型、MCP 与 Docker，覆盖项目和学习流程。`--scenario project`、`learning`、`invalid` 可单独选择；失败场景检查前序结果保留、后续步骤不执行。

`python scripts/windows_interactive_terminal_e2e.py` 覆盖真实项目测试失败、修复、复测；`python scripts/windows_autonomy_e2e.py` 覆盖自主模式与逐步模式切换。真实模型和外部服务会影响运行，验收失败不能用伪造结果替代。
