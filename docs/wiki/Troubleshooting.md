# 常见问题

## 页面提示凭据无效或连接失败

使用当前 GUI 启动进程打印的完整地址。只打开旧的端口地址可能没有凭据；服务重启后旧凭据会失效。不要把完整启动地址分享给他人。界面更新后重新构建 `web`，重启 GUI 并重新打开地址。

## 页面有新功能，模型仍说不能联网

当前普通对话支持公开新闻与 Wikipedia 查询。先确认运行的是当前开发分支与新后端，检查工具是否被禁用以及当前审批模式。旧回复和失败提交不会自动改写，升级后重新发送问题。

## 搜索不到“昨天”的新闻

新闻按北京时间计算区间，再按条目发布时间过滤；不会用旧新闻补位。RSS 网络限制、查询词和源覆盖可能导致无结果。可调整主题，但不要把没有来源的生成文本当成检索结果。

## 仍频繁等待审批

到“权限与文件”检查当前对话模式。逐步确认会要求每步确认；平衡模式会对代码、覆盖和未单独授权的终端输入确认。可信任务可以明确开启自主执行，工具禁用仍优先。切换模式不会自动重放已有待审批步骤。

## 哪里批准下一步

任务模式选择任务，在详情区使用审批按钮，核对预览；Python 与终端命令按提示输入 `EXECUTE`。持续终端的 Agent 审批在终端面板中，不在普通任务详情里。准备任务只填入草稿，还需要点击提交。

## 文件读写失败

使用本机绝对路径，确认文件存在和系统访问权限。平衡模式下工作目录外读取需路径授权。官方 Filesystem MCP 还受它自己的允许根目录约束，自主模式不会取消服务侧限制。

专用写入工具只支持工作目录中的指定文本类型，覆盖需匹配原内容摘要。确认 Node.js 在 PATH 中，并在仓库根目录运行 `npm ci --prefix integrations/filesystem`。需要通用文件操作时使用已授权的终端，并明确路径。

## Python 步骤失败

检查 Docker 是否运行、Linux 容器是否可用、`python:3.10-slim` 镜像是否存在。查看任务结果或错误，不因模型说“完成”就忽略退出状态。需要被后续引用的 Python 输出应为单个 JSON，不混入日志或 Markdown。

## 终端打不开或没有输出

持续终端需要支持 ConPTY 的 Windows 和 `integrations/terminal/requirements.txt` 中的依赖。目录必须存在；本机终端不支持 UNC 起始目录。检查工具是否禁用，以及打开时是否确认了本机权限。

终端输出包含输入回显，要等待实际返回。程序可能正在等待交互输入；可直接输入回答，或使用 Ctrl+C。关闭面板不会结束终端，关闭终端才清理进程树。服务崩溃的终端只保留记录，不恢复进程或重放命令。

## 规划失败或任务停在“需要核查”

检查模型配置、网络、输入路径、工具契约和结果证据。状态不确定时不要反复提交或删除认领记录。CLI 可用 `/诊断`、`/失败` 查看原因；恢复和重规划需按提示确认。修正问题后再明确创建新请求。

## GUI 与 CLI 看不到相同记录

确认同一数据目录和会话，CLI 用 `/sessions` 与 `/use ID`。GUI 的 `--data-dir` 不会自动更改另一个 CLI 进程的配置。普通对话历史与旧版工具 Agent 的检查点不是同一类记录。

## 如何报告问题

提供版本或提交号、Windows/Python 版本、复现步骤、预期与实际结果，以及已去除密钥和私人数据的日志片段。运行数据和完整启动地址不要直接上传。[提交 Issue](https://github.com/weiyu687/EduClaw/issues)。
