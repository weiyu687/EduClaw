# 架构与安全

## 调用链

GUI（TypeScript / React）或 CLI 接收用户输入，Python 服务读取会话和权限。普通对话使用共享历史与受限搜索；任务规划器选择已适配工具并生成最多 12 步计划。调用在 MCP 传输前经过权限网关和参数契约校验，结果写入 SQLite 账本及结果仓库。

持续终端由独立本机服务维护 ConPTY 会话，GUI 与 CLI 共享终端 ID。终端 Agent 观察实际输出，再提出输入、等待或结束；原有任务规划使用单次 `run_terminal`，两条入口并存。

## 用户控制的审批策略

| 层次 | 范围 |
| --- | --- |
| 对话审批模式 | 当前对话的 strict / balanced / autonomous，重启保留，新对话默认 balanced |
| 工具禁用 | 当前数据目录的所有会话，优先于自主执行 |
| 文件读取授权 | 指定路径及单次或会话范围 |
| 工具合同与适配器 | 限制参数、输入输出、支持的能力和文件范围 |
| 操作系统权限 | 本机终端使用启动用户权限，不自动提权 |

`core/security/autonomy.py` 保存模式和变更记录。模型工具中没有修改审批模式的入口。逐步确认收紧自动调用；平衡模式保留低风险自动执行；自主执行需用户明确确认后放开已适配工具的逐步审批。

自主执行可以通过通用终端读写或删除本机文件、联网、安装程序及修改用户有权限修改的系统配置。**目录不是终端沙箱，模型对敏感操作的判断也不是隔离保证。** 选择自主模式即授予这个对话相应本机能力。

## 人工确认与策略授权

人工审批先展示真实参数，再签发短期票据；票据绑定会话、任务、步骤和内容摘要，过期或参数变化需重新预览。Python 代码审批与实际解析后的代码绑定。

自动任务和终端 Agent 在调用前重新检查策略。按策略自动执行记录为策略授权，不伪造人工审批事件。改变模式不会重放已有待审批输入，不撤销已发生的文件或网络效果；已开始的操作需单独停止。

## 防止重复执行

任务调用前持久认领。结果不确定或写入结果失败时，保留认领并停止，不通过重试工具来掩盖未知状态。结果保存摘要用于核验；先保存结果，再推进检查点。文件覆盖绑定原内容摘要，避免静默覆盖预览后变化的内容。

终端输入有请求标识，同一请求重试不重复写入；相同标识换参数会被拒绝。关闭终端使用 Windows Job Object 清理其进程树，但不回滚已产生的外部效果。

## 本机服务与数据

GUI 仅监听回环地址，启动凭据通过地址片段交给前端后从地址栏移除。重启会轮换凭据。终端服务同样仅本机连接并验证凭据；它不是远程共享终端。

数据目录保存会话、规划、任务状态、结果、权限与终端记录。不要把运行数据库或凭据提交 Git。备份需保证整个目录一致；删除会话使用软删除并清理所属终端，历史审计不会物理清空。

## 仍需完善

尚无完整生产安全审计、插件签名、多用户鉴权、第三方工具通用进程隔离或副作用自动补偿。任意 MCP 服务器的发现结果、Skill 文本、文件和网页内容都不能作为执行授权。
