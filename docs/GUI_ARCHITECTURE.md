# GUI 基础架构评估（5.12.3c）

2026-10-12 更新：已实现 TypeScript + React + Vite 本地工作台第一增量。
可查看任务、步骤依赖、结果证据，并预览确认暂停、恢复暂停和取消。
完整审批中心、任务创建和重规划界面尚未上线。

`core/security/task_context.py` 为 CLI 和当前 GUI 提供同一任务列表、稳定编号、
选择、进度、结果摘要和操作解析。服务输出只包含说明、待预览读取或内部命令；
不执行 MCP，也不授予权限。CLI 保留旧命令兼容层。

下一步应把 CLI 内的审批与执行实现提取到独立 Application Service，返回结构化
审批视图与事件，随后让 CLI 和 GUI 都调用它。不能把内部命令拼接器直接暴露为
公网 API，也不能让 GUI 写 SQLite。

## 技术方案

先采用本地 Web 原型评估交互，后决定桌面外壳。Windows 上 Web 原型复用已有
Python 服务与 SQLite 状态，迭代和键盘测试成本低。Electron 带完整 Chromium，体积较大；
Tauri 依赖系统 WebView 和 Rust 构建链，需要另行验证安装与分发。当前没有引入
任何外壳依赖；GUI 启动时新增仅本机可访问的监听端口。

当前 `core/gui/server.py` 本地 API 仅绑定 loopback；使用每次启动随机身份凭据、Origin 校验和
拒绝跨域访问；变更操作防 CSRF；页面刷新不能自动重新发送审批或执行请求。
事件使用持久化递增序号，断线重连按序号补读；任务状态以服务端检查点为准。

`core/gui/service.py` 复用 TaskContext、TaskLifecycle 和结果仓库。前端每 3 秒读取
快照，API 同时提供按游标读取的账本事件，尚未接入前端事件订阅。控制操作经
一次性、限时、绑定任务状态的票据确认；不通过 HTTP 暴露 CLI 命令执行器。
界面从不授予文件/代码权限，也不启动工具。仅解除暂停不是恢复成功证据检查点。
界面部署和安全边界见 [web/README.md](../web/README.md)。

## 首个原型用户旅程

任务首页（名称、编号、进度、下一步）→ 任务详情（步骤、依赖、结果）→
审批中心（准确文件范围或完整代码、拒绝、确认）→ 结果中心（摘要、证据）。
重规划页显示增加/删除/修改与已完成结果继承。默认不显示 token 和内部 ID。

验收要覆盖键盘操作、空状态、加载、模型失败、断线、重复点击、重启和与 CLI
交叉操作。同一任务的两个入口必须通过同一原子认领，不能靠前端禁用按钮防重放。
