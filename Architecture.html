架构与安全

数据流

TypeScript / React
  → 本机 HTTP API（凭据 + 来源校验）
  → Workspace（会话挂载、异步规划、提交去重）
  → LangGraph 待审批检查点 + DAG + 目标标准
  → AutoRunner + Code/Read/ToolStepService（权限策略与一次性认领）
  → MCP / Docker
  → 不可变结果仓库 + 执行账本 + 检查点更新

前端不连接 SQLite，不直接调用 MCP，不保存模型密钥。CLI 与 GUI 共用 Python 执行服务，竞争同一原子认领记录。

本地 API

默认仅监听 loopback。数据请求必须带当前服务的 Bearer 凭据，POST 还要求准确同源 Origin。服务拒绝跨域、外部 Host、未知接口与额外字段；请求体限制为 32 KiB。

凭据通过 URL fragment 交给页面后移除，存在当前标签页的 sessionStorage。此模式是本机单用户原型，不是局域网或公网多用户服务。

审批与执行

需要人工审批的控制与执行先预览再确认，票据有效 120 秒，绑定任务状态并先消耗后执行。Python 的实际代码、引用结果与任务身份绑定到摘要。worker 只接收任务身份与审批摘要，重新读取并校验持久化代码。

工具执行前写入持久认领。结果保存失败或执行结果不确定时，保留认领，不自动重放。成功结果先写入不可变结果仓库，再推进账本与检查点。结果仓库保存 SHA256，供恢复与证据检查使用。

数据文件

任务与会话使用现有 SQLite 数据库。新增 educlaw_gui.sqlite3 保存会话挂载与提交记录，包含任务目标和技能快照，应作为本机任务数据对待。

服务重启后，未完成规划显示中断，不自动调用模型重试；稳定任务身份避免同一提交被静默重复创建。停止服务和备份时应等待在途任务结束，保留所有关联数据库及 SQLite WAL 文件的一致性。

尚未实现

第三方进程隔离、插件签名、通用副作用补偿、完整 GUI 重规划、多用户鉴权和自动更新安装包。不能将目前的工具注册声明视为通用安全隔离。

自动任务在每个步骤前检查当前工具策略和路径范围；自动执行不生成一次性人工批准凭据。覆盖已有文本必须绑定原内容摘要，代码必须绑定精确代码。官方文件服务仅接收工作目录作为允许根目录，网关与适配器各自校验范围。文件操作锁协调 EduClaw 进程，不是对其他本地程序的隔离。
